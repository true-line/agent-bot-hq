# Stage 2a Messages qualification seam

This is the narrow test-provider route for [Platform #68 T03](https://github.com/true-line/agent-bot-platform/issues/68) and [HQ #231](https://github.com/true-line/agent-bot-hq/issues/231). It does not add a live Claude provider or enable a protected profile.

The current `hq/claude-qualification-http.mjs` component fixture runs under a **harness credential UID**, not HQ's UID. For a same-UID component probe its `socketPath` is in that UID's private 0700 directory and the Unix socket is 0600. For a distinct runner UID it requires a credential-owned, runner-private-group 2750 immediate parent and creates a 0660 socket inheriting that exact group. It checks the kernel peer UID on each HTTP request with `getpeereid` (or `SO_PEERCRED` on Linux) before reading the body. Machine must provision and verify a traversable, non-replaceable ancestry for that group endpoint; this module verifies the immediate parent and socket inode, not the whole installation. The [PDR-0052](https://github.com/true-line/agent-bot-platform/blob/main/docs/04-decisions/PDR-0052-process-isolation-for-harness-egress.md) two-destination rule applies separately to two confined processes:

| Process | Assigned outbound Unix paths | Local listener |
| --- | --- | --- |
| Credential-UID HTTP bridge | Its Soul member socket; HQ's per-harness NDJSON broker socket | Assigned HTTP broker socket |
| Soul-runner-UID stock ACP | Its Soul member socket; the bridge's HTTP broker socket | None |

The bridge HTTP socket **is the ACP launch assignment's broker path**, not a third allowed destination. The bridge's listening socket is not an outbound egress path in its own profile. Both profiles must refuse direct IPv4/IPv6, the shared HQ broker socket and sibling launch sockets. The HTTP `x-api-key` is an inert stock-client placeholder, never authorization. Machine and HQ still need a reviewed dual-process launch plan and exact UID/path matching before this can qualify physically; no policy expansion is authorized by this component change.

For protected integration, the two processes must be pinned to the same Soul installation, start and one-use Machine plan but **different UIDs**: the sidecar uses the per-harness credential principal that HQ's broker accepts, and stock ACP uses the untrusted runner principal dedicated to that Soul installation. The sidecar alone holds the member bootstrap token and HMAC-bound HQ session; ACP gets neither. Machine must demonstrate that ACP cannot read sidecar state or connect to HQ's NDJSON endpoint, and that the sidecar cannot connect to ACP's other paths. The group-reachable HTTP mode is a code path only; Machine's reviewed endpoint provisioning, a runner-accessible Souls member socket, and a private authenticated token handoff are still needed. The runner-specific HQ admission endpoint in HQ #226 is a different socket and does not provide this member or HTTP path. Until those contracts exist, this code remains a cooperative component proof and protected launch remains closed.

The sidecar receives an existing member session from `sdk/member-session.mjs`: member-token bootstrap, HQ challenge, HMAC bind, then one captured broker request. It accepts only policy-limit GET and a streamed Messages POST with the exact model and last-user prompt from the owner-approved qualification plan. Ancillary POSTs return 422 without broker delivery. It caps HTTP bodies at 256 KiB, enough for the measured 87,619-byte stock ACP main request. The reply uses Anthropic Messages SSE framing.

`hq/qualification-provider.mjs` is an opt-in plugin; production HQ does not install it by default. It takes the exact raw test-provider configuration bytes pinned by Machine's `test_provider.configuration_sha256`, verifies their SHA-256, then parses only `{model,prompt,response_text}`. Model, prompt digest and fixed response all come from those pinned bytes, never from member frames or free constructor fields. Its caller must inject a callback that verifies the **Machine-authorized plan ID, digest and provider config digest** against the admission-checked bound runtime, expiry and intended one-use operation. The plugin persists a consumed plan digest in HQ's store before returning a fixed text response; it refuses that digest after HQ restart. Machine's own persistent one-use authorization must also refuse replay if HQ's store is unavailable, rolled back or replaced. It holds no vendor credential and makes no network call. `() => true` is only a test fixture, never a production authorization callback. Until Machine supplies that callback and the exact socket rule, this code is a reviewable component seam, not physical T03 evidence.

The current provider returns one text value, which the bridge emits as one Messages `content_block_delta`. This proves stock framing and broker routing, not incremental HQ streaming. Two separately observable HQ deltas and a terminal frame are still needed for any streaming claim.

The full inference route, provider credentials, tool streaming, budget ledger and live vendor calls remain the Stage 2b work tracked by [HQ #208](https://github.com/true-line/agent-bot-hq/pull/208). A physical T03 acceptance run still needs the pinned release artifact, actual HQ-started Soul, Machine plan, stock ACP and signed host receipt.
